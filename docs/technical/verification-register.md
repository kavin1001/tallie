# Verification register

**Updated:** September 26, 2026 (America/New_York; machine evidence timestamps use UTC).  
**Design:** [Technical reference](../payments-technical-design.md)

Use this register to prevent a proposed capability from becoming an assumed fact. `Passed locally` and `Documented` do not mean sandbox-tested or production-approved. Owners are roles until people are assigned. A gate blocks only the dependent live feature, not unrelated design/prototyping.

**Current partner status:** the founder confirms Natural approved P2P; dedicated production credentials and callback registration are configured; customer/device/bank verification is still needed. Program approval is distinct from credential binding, observed bank funding/cash-out, device authorization and founder release approval.

## How to close a gate

Attach sanitized evidence: exact version/account environment, date, command/test ID, expected and observed result, limitations, and owner. Documentation findings link the precise primary source. Partner confirmation records a reference, not private credentials. Device checks identify OS/browser/app versions. If behavior contradicts the document, fix the design/adapter and add a regression test before marking passed.

For provider contract changes, rerun the public checker and affected integration tests. A new source hash triggers review; it is not permission to regenerate and deploy unchecked adapters. Keep earlier evidence when it explains a migration or incident.
